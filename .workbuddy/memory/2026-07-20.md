## 任务：分析项目并写架构教程（高并发 / 缓存 / 消息队列）

- 产出教程文档：`docs/architecture-concurrency-cache-mq.md`
- 三大主题逐行分析并对照源码：

### 高并发
- WebSocket Hub 单 owner-goroutine 模型（pkg/websocket/hub.go:42 Run() 用 select 串行处理 register/unregister，避免并发写 map）
- 每连接双 pump（ReadPump/WritePump）+ 发送缓冲 channel(256) + 背压剔除（满缓冲即 unregister）
- keepalive 后台调度：context + WaitGroup + Ticker（internal/keepalive/manager.go）
- SSE：行情用 c.Request.Context() 检测断开；AI 用 context.Background() 解耦请求生命周期实现断线续传
- fire-and-forget goroutine 把 Kafka 发布移出请求路径；AI 会话落库用 per-chat sync.Mutex（sync.Map 索引）

### 缓存
- 泛型 RedisCache[T]：`GetOrLoad` 内置 singleflight 防击穿 + 空值缓存防穿透 + TTL 随机抖动防雪崩（pkg/cache/redis_cache.go）
- 行情：Sorted Set + TTL 清理 + keepalive 轮询 write-behind
- AI 流式：Redis List 作重放缓冲（AppendStreamChunk + SubscribeStream 50ms 轮询），断线续传
- 计数器走 PG 事务 gorm.Expr，不用 Redis INCR

### 消息队列（重要发现）
- 三层：pkg/kafka（封装）+ internal/service/kafka_helpers.go（发布）+ internal/kafka（handler）
- **关键 BUG**：producer.go 的 Writer 被写死绑定 TopicNotification，Publish 未设置 Message.Topic，导致所有事件（含 post-event / user-event）实际全进 TopicNotification → post-event-group 与 cache-group 永远收不到消息，ES 索引与缓存失效实际失效（仅靠 TTL 兜底）。修复方向：Publish 按消息设置 Message.Topic，或为不同 topic 创建独立 Writer。
- 消费者：消费组 + 自动提交（at-least-once）+ Redis SETNX 幂等；无重试/死信
- 另：`global.JWTBlacklist` 为无锁普通 map 但 grep 确认未被引用（死代码）
